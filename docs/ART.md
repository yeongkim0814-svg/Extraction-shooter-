# 그래픽·모델링·에셋 가이드

## 1. 그래픽 디렉션: 세미리얼, 전환 가능

**전환 가능 구조 (핵심 원칙):** 씬의 모든 머티리얼은 소수의 프로젝트 마스터 셰이더(`.gdshader`)에서 파생한 `ShaderMaterial`이다. M10에서 스타일라이즈드로 전환하기로 하면 마스터 셰이더·컬러 보정·텍스처 세트만 교체하고 씬은 재작업하지 않는다.

| 마스터 셰이더 | 용도 |
|---|---|
| `master_opaque.gdshader` | 환경·소품·캐릭터 일반 |
| `master_foliage.gdshader` | 식생 (바람, 알파 컷) |
| `master_decal` (Decal 노드 + 텍스처 규칙) | 오염·균열·표식 |
| `weapon_fp.gdshader` | 1인칭 무기 (별도 FOV, 벽 관통 방지) |

마스터 셰이더는 Mobile·Compatibility 두 렌더러에서 모두 컴파일되는 기능만 쓴다.

### 렌더러별 그래픽 범위

| | Android (Mobile 렌더러) | 웹 (Compatibility 렌더러) |
|---|---|---|
| PBR 머티리얼 | 지원 | 지원 |
| 실시간 그림자 | 방향광 1개 | 방향광 1개 (저해상도) |
| 글로벌 일루미네이션 | 라이트맵(LightmapGI) | 라이트맵 |
| 화면 공간 효과(SSAO 등) | 제한적 | 없음 → AO는 텍스처에 베이크 |
| 후처리 | 톤매핑·컬러 보정·글로우 | 톤매핑·컬러 보정 위주 |

세부 지원 범위는 M4에서 두 플랫폼 실측으로 확정한다. **웹의 세미리얼 표현은 지오메트리·라이팅보다 PBR 텍스처 품질과 베이크된 AO·라이트맵에 의존**한다.

### M4 실측 결과 (테스트 씬, 2026-10-08)

| 항목 | Android (Galaxy Tab S 계열 추정, Mali-G925-Immortalis MC12) | 웹 (Chromium 헤드리스, SwiftShader) |
|---|---|---|
| 렌더러 | mobile (Vulkan) | gl_compatibility (WebGL2) |
| 측정 FPS | 120 (기기 주사율 상한) | 3~4 (소프트웨어 렌더링이라 참고용) |
| 그림자 | 방향광 그림자 정상, 가장자리 계단 현상 있음 → M10에서 그림자 해상도·필터 조정 | 정상 |
| 재질(금속·녹·발광) | 정상 | 정상 |
| 라이트맵 굽기 | 편집기에서 성공 (씬에 메시 노드 + UV2 + 정적 GI 필요) | 해당 없음 |

- 라이트맵은 씬에 실제 메시 노드가 있고 UV2가 켜져 있어야 굽힌다. 코드로 만든 도형은 굽기 대상이 되지 않는다.
- 굽기 결과(.lmbake, .exr)는 저장소에 커밋하지 않는다 (M10에서 `.gitignore` 정책 확정).


### 라이팅

- 주력: 라이트맵(LightmapGI) + 리플렉션 프로브, 실시간 방향광 1개
- **라이트맵 베이크는 GPU 렌더러가 필요** → 탭 에디터에서 가능한지 M4에서 확인. 불가하면 PC 세션에 맵 단위로 몰아서 베이크
- 안개: 분위기 + 원거리 시야 제한 겸용. 실내외 경계는 오클루더(OccluderInstance3D)로 컬링

### 품질 티어 (설정에서 선택, 기기 자동 판별)

| 티어 | 대상 | 렌더 스케일 | 그림자 | 후처리 | 텍스처 |
|---|---|---|---|---|---|
| Low | 저가 폰·모바일 웹 | 0.7 | 끔 | 톤매핑만 | 512~1K |
| Mid | 중급 폰·태블릿 | 0.85 | 저해상도 | +컬러 보정 | 1K |
| High | 고급 폰·데스크톱 웹 | 1.0 | 기본 | 전체 | 1~2K |

**목표 프레임:** 중급 안드로이드 30fps 고정, 고급 기기·데스크톱 웹 60fps.

## 2. 폴리곤·텍스처 예산

| 에셋 | 트라이 | 텍스처 | LOD |
|---|---|---|---|
| 1인칭 무기 (부품 합계) | 6~10k | 2K (1세트) | 없음 |
| 월드 드롭 무기 | ≤2k | 1인칭 텍스처 공유 | 자동 LOD |
| 1인칭 팔 | 5~8k | 1K | 없음 |
| 적 캐릭터 | 10~15k | 2K 아틀라스 | 자동 LOD |
| 모듈 환경 조각 | 200~2k | 타일·트림 텍스처 공유 | 자동 LOD |
| 소품 | 100~1.5k | 아틀라스 | 자동 LOD |

Godot은 임포트 시 메시 LOD를 자동 생성한다 (수동 LOD 제작 불필요).
화면 전체 상한: 트라이 ≤300k, 드로우콜 ≤150(모바일), 텍스처 메모리 ≤500MB (웹 ≤300MB).

## 3. 모델링 도구와 역할

| 도구 | 기기 | 담당 |
|---|---|---|
| **Nomad Sculpt** | 갤럭시 탭 (S펜) | 무기 부품, 소품, 캐릭터 스컬프트, 버텍스/PBR 페인팅 |
| **Godot 에디터** | 갤럭시 탭 | 모델 조립, 소켓(Marker3D) 지정, 머티리얼, 레벨 그레이박스(CSG) |
| **Mixamo** (웹) | 탭 브라우저 (데스크톱 모드, 동작 확인 필요) 또는 PC | 캐릭터 자동 리깅·애니메이션 |
| **Blender** (선택) | PC 세션 | Nomad로 부족할 때만: 리토폴로지·UV·노멀맵 베이크·정밀 하드서피스 |
| CC0 에셋 | — | 텍스처·HDRI·플레이스홀더 모델 |

### Nomad Sculpt로 게임 무기 만드는 흐름

1. 기본 도형(박스·실린더)으로 부품 형태 잡기 → 불리언·트림으로 각진 면 만들기
2. (필요하면) 디테일 스컬프트
3. 데시메이트 / 리메시로 트라이 예산까지 줄이기
4. 자동 UV → PBR 페인팅 (색·거칠기·금속성)
5. **glTF(.glb)로 내보내기** → Godot으로 임포트

한계와 대응:
- 스컬프트 도구라 정밀한 기계 디테일·깔끔한 엣지 흐름에 약함 → **부품을 작게 나눠 모델링** (모딩 부품 트리와 자연히 맞음), 세부는 지오메트리 대신 텍스처로 표현
- 소켓용 빈 오브젝트를 만들 수 없음 → 소켓은 Godot에서 부품 씬에 `Marker3D`로 추가
- 리깅 기능 없음 → 캐릭터는 Mixamo
- 결과 품질이 목표에 못 미치는 부품만 PC 세션에서 Blender로 교체

## 4. 무기 모델 사양 (코드와의 계약)

- 단위 m, Y-up, 총구 방향 −Z (Godot 전방 규약), 원점 = 그립 중심 (부품은 장착 소켓 기준)
- 형식: glTF 2.0 (`.glb`). 부품 1개 = 파일 1개 = 상속 씬 1개
- 소켓 (부품 씬의 `Marker3D` 이름):
  - `SOCKET_Muzzle`, `SOCKET_Optic`, `SOCKET_Magazine`, `SOCKET_Ejection`, `SOCKET_Barrel`, `SOCKET_Handguard`, `SOCKET_Stock`, `SOCKET_Grip`
  - `SOCKET_LeftHand` (왼손 IK 대상)
- 움직이는 부품은 분리 메시: 슬라이드/볼트, 탄창, 방아쇠
- 애니메이션: 재장전(tactical/empty)·장착은 키프레임 또는 코드 트윈, **반동·흔들림·ADS는 코드 절차적**
- 아이콘: `SubViewport`로 자동 렌더 (셀당 64px, 회전 아이콘 포함). 부품 구성이 바뀌면 재생성

## 5. 환경: 버려진 산업단지

### 모듈 키트 (4m 그리드 스냅)

- 벽 4×4, 바닥 4×4, 문 개구부 2×2.5, 계단, 철골 기둥, 지붕 트러스
- 대형 구조: 창고, 사무동, 컨테이너 야적장, 탱크·파이프 구역, 경비초소
- 대부분 단순 형태라 **스컬프트 불필요**: 기본 도형 + CC0 PBR 텍스처(콘크리트·녹슨 금속·골강판·아스팔트) + 오염 데칼로 세미리얼 질감 확보
- 루팅 컨테이너 소품(서랍장·공구함·나무 상자·군용 상자·캐비닛·더플백)은 Nomad Sculpt

### 레벨 디자인 순서

1. 그레이박스: Godot **CSG 노드**로 탭에서 동선·교전 거리·탈출 지점 배치
2. 플레이테스트 (AI·수색·탈출 루프)
3. 모듈 메시로 교체 → 라이트맵 베이크

## 6. 캐릭터·애니메이션

- 휴머노이드: Nomad Sculpt 모델 → Mixamo 자동 리깅 → Godot 임포트(FBX 기본 지원), 리타기팅으로 애니메이션 공유

## 7. 에셋 조달 규칙

1. 라이선스 명확한 외부 소스: Poly Haven·ambientCG (CC0), Godot Asset Library, Mixamo
2. Higgsfield: `generate_image`로 콘셉트 아트·Nomad 작업용 참고 이미지, `generate_3d`로 블록아웃(최종 품질 아님)
3. Nomad Sculpt 직접 제작 → 부족한 부분만 Blender

- 모든 외부 에셋은 [ASSET_LICENSES.md](ASSET_LICENSES.md)에 출처·라이선스 기록
- 바이너리는 일반 Git으로 관리 (클라우드 환경에서 LFS 업로드 불가, MVP 에셋은 작음). 대형 에셋이 늘면 재검토

## 10. M10 그래픽 패스 (산업단지)

### 스타일 결정
세미리얼 · 흐린 산업단지 무드 (사용자 콘셉트 보드 docs/art/industrial_mood.webp)

M10 체크포인트 결과: 스타일라이즈드로 전환하지 않고 세미리얼을 유지한다. 위 1장의 "전환 가능 구조" 원칙은 그대로 두되, 산업단지 씬의 재질은 `IndustrialMaterials` 한 곳에서 만든다.

### 재질 라이브러리 (`scripts/game/world/industrial_materials.gd`)
- 모든 텍스처는 `NoiseTexture2D`(알베도·거칠기·노멀 디테일)이고 최대 512 px. 한 번 만들어 캐시하고 모든 재질이 공유한다. UV는 트라이플래너라 메시에 UV가 없어도 된다.
- 재질은 약 25종으로 작게 유지해 메시를 재질별로 합친다 (맵 메시 인스턴스는 60개 미만).
- 콘크리트(밝은·어두운), 젖은 아스팔트, 바닥 흙, 녹슨 금속, 골판 금속, 컨테이너 도장(빨강·녹·청록·파랑·황토), 어두운 강철, 벽돌 공장 외벽, 발광 창(밝은·어두운), 웅덩이, 나무, 램프(발광), 빛 기둥(가짜), 잡초, 표식 띠.
- 개발 씬(combat_test·ai_test)은 `restyle_csg()`로 콘크리트·아스팔트만 입힌다 (배치·게임플레이 불변).

### 조명·분위기 레시피
- 하늘: `industrial_sky.gdshader` (흐린 회청색 + 낮은 태양 글로우).
- 톤맵 AgX, 노출 약 0.96, 대비 1.12, 채도 0.78 (`assets/env/industrial_env.tres`). 글로우 약하게, 깊이·높이 안개(회청색).
- 태양: 낮은 각도, 그림자 최대 거리 약 40 m, 분할 2개 이하.
- 실내: 발광 창, 가짜 빛 기둥(반투명 발광 메시), 발광 램프. 추가 실시간 광원 없음.
- 반사 프로브 2개(부지·공장 홀), 갱신 한 번(UPDATE_ONCE).
- 연기: 모바일 GPUParticles3D, 웹 CPUParticles3D (적은 수). 잡초는 MultiMesh 한 개.
- Mobile 렌더러에 없는 SSR·SSAO·SDFGI·볼류메트릭 안개는 쓰지 않는다. 웹(gl_compatibility)에서도 검게 나오지 않는다.
- 적(올리브 캡슐)은 약한 자체 발광과 림 라이트로 어두운 실내에서도 보이게 한다 (시체는 끔).

### 품질 단계 (`scripts/core/graphics/graphics_tier.gd`, 적용: `scripts/game/settings/graphics_quality.gd`)
| 항목 | LOW | MID | HIGH |
|---|---|---|---|
| 렌더 배율 | 0.7 | 0.85 | 1.0 |
| 그림자 | 끔 | 1분할 30 m | 2분할 45 m |
| 글로우 | 끔 | 켬 | 켬 |
| 높이 안개 | 끔 | 켬 | 켬 (태양 산란 0.25) |
| 연기 파티클 | 40% | 70% | 100% |
| 잡초 밀도 | 30% | 65% | 100% |
| MSAA | 끔 | 2x | 2x |
| 반사 프로브 | 끔 | 켬 | 켬 |

기본값: 안드로이드 MID, 데스크톱 웹 HIGH. `?quality=low|mid|high`로 강제 가능. 개발 키 **F2**(터치는 네 손가락 동시)로 순환하고 토스트와 `RAID: quality <단계>` 로그를 남긴다. (Q는 무기 전환 키라 쓰지 않는다.)

### 예산·측정
- 목표: 갤럭시 탭 Mobile 렌더러, 레이드(적 6명)에서 60 fps, 드로우콜 약 150 이하.
- 5초마다 `RAID: render draw_calls=<n> objects=<n> primitives=<n> fps=<n>` 로그. 헤드리스 SwiftShader 수치는 실기기와 무관하다 (웹 스모크에서 드로우콜 약 120~200, fps는 한 자리).
- 실기기 확인 절차: docs/M10_TABLET_CHECKLIST.md

## 스타일 D: 트림시트 스타일라이즈드 PBR (비교 비네트 `?scene=style_d`)

기법은 Godot 4 데모 "Abandoned Spaceship"(Perfoon, MIT)을 따른다. 에셋은 쓰지 않았고 텍스처는 `tools/gen_trim_sheets.py`가 직접 만든다.

- **트림시트**: 1024 px 시트 2장(콘크리트·벽돌 / 금속·컨테이너)에 가로 띠(줄)가 쌓여 있다. 맵 4장(albedo, ORM, normal, mask: R 높이·G 페인트·B 발광) + 512 px 디테일. 줄 배치는 `scripts/core/geometry/trim_layout.gd`(테스트가 `trim_layout.json`과 대조).
- **UV 사상**: `TrimUv` + `MeshBuilder.trim_strips`. U는 월드 미터를 256 px/m로 센다(4 m = 한 바퀴), V는 줄 범위가 면의 아래~위에 걸린다. 줄 위아래 가장자리에 구워 둔 닳은 하이라이트·AO가 모따기에 닿는다. 면이 줄 자연 높이의 2.6배보다 높으면 소품 코드가 판을 쌓는다(`StyleFactory.slab`).
- **재칠 셰이더** `assets/shaders/trim_recolor.gdshader`: `ALBEDO = mix(albedo, albedo * paint_color, paint_mask) * detail`, `ROUGHNESS = orm.g * roughness_scale + (1 - detail.r)`. 소품마다 색만 다르다 (`TrimMaterials`: 녹슨 빨강, 청회색, 올리브, 따뜻한 노랑, 바랜 흰색).
- **라이트맵 대용**: `StyleBake`가 정점마다 반구 레이(AO 6 + 하늘 2 + 램프)를 쏴 `COLOR`(R AO, G 하늘 가시성, B 램프 따뜻함)에 한 번 굽는다. `MeshBuilder.subdiv_max`가 큰 면을 쪼개 정점을 만든다. 라이트맵이 있으면 쓰지 않는다 (`StyleBake.lightmap_present`, 셰이더 `vertex_bake = 0`).
- **실제 라이트맵 (태블릿)**: `godot --headless --path . --script tools/build_style_d_bake_scene.gd` -> `scenes/dev/style_d_bake.tscn`(+ `scenes/dev/style_d_bake/*.res`). 에디터에서 LightmapGI > Bake Lightmaps.
- **효과**: Forward+ 전용 SSAO·SSIL·볼류메트릭 안개·TAA 대신 정점 AO, 빛줄기·램프 원뿔 카드, 먼지 입자(웹 CPU / 모바일 GPU), 반사 프로브 한 번 갱신, 은은한 글로우, 담쟁이·고사리 알파 카드.

## 11. 아트 바이블 v2: "빛이 주인공인 단순 형태 + 트림 디테일" (확정 2026-10-09)

10장의 세미리얼 결정과 스타일 A~D 비교를 대체한다. 참고 데모 두 개를 합친 방향이다.
- **Desert Light** (RPicster, MIT): 텍스처를 거의 쓰지 않고 간접광·안개·색 보정으로 그림을 만든다.

### 11.6 조명
- **간접광**: 구역별 LightmapGI (바운스 2~3, 발광 표면 포함). 구역 = 굽는 단위 = 탭에서 한 번에 굽는 크기. 프로브는 낮게(탭 안정성).
- **실시간 빛**: 손전등, 총구 화염, 깜빡이는 램프 구역당 1~2개만. 태양은 실시간 그림자(동적 물체용), 간접은 구움.
- **볼류메트릭 대용**: 빛줄기 카드, 안개 카드(그라데이션 쿼드), 높이 안개 + 태양 산란, 먼지 입자, 램프 헤일로 스프라이트.
- **색 보정**: 필믹 톤매핑(낮은 노출·높은 화이트), 색 보정 곡선(그림자 청록 #08192A 쪽, 밝은 곳 크림 #F2EDD9 쪽), 약한 글로우.

### 11.8 텍스처 v2 구현
- 생성기: `tools/gen_textures_v2.py` -> `assets/textures/v2/`. 트림 `t1`(구조) `t2`(금속) `t3`(설비) x `{albedo,orm,normal,mask}.webp`, 바닥 `ground_{asphalt,concrete,gravel}_{albedo,orm,normal}.webp`, `detail_v2.webp`(512 px 선형: R 6 m 얼룩 / G 1.5 m 때 / B 잔 점, 0.5 = 중립), `decals.webp` + `decals.json`, `kit_layout.json`.
- 채널 규약은 스타일 D와 같다: albedo sRGB, ORM = R AO / G 거칠기 / B 금속성, normal OpenGL(Y+), mask = R 높이 / G 페인트 / B 발광. 256 px/m, 시트 1024, U 4 m 주기, 줄 사이 4 px 여백.
- "면" 줄(wall, panel, band, sill, corrugated, plate, beam, cabinet, duct)은 가운데 60% 알베도 명도 편차 <= 0.06을 생성기가 검사한다 (넘으면 비정상 종료). 줄 배치는 `scripts/core/geometry/kit_layout.gd`.
- 셰이더: `kit_trim`(트림 + 페인트 재칠, 라이트맵용), `kit_flat`(단색 면 + 약한 얼룩·바닥 때·비 줄무늬), `kit_ground`(월드 XZ 4 m 타일, 두 배율 + 37도 회전 샘플 혼합). 재질은 `scripts/game/world/kit_materials.gd`.
- **kit_ground 정점 색 규약** (정점 색이 없으면 COLOR = 흰색이므로 반전 채널): 젖음 = 1 - R, 흙 = 1 - G, 이끼 = 1 - B. 흰색 (1,1,1) = 마른 맨바닥. 웅덩이는 R을 0으로 칠한다.
- 재생성: `python3 tools/gen_textures_v2.py && godot --headless --path . --import && python3 tools/gen_textures_v2.py --patch-import` (그다음 한 번 더 `--import`). 미리보기: `--preview 경로.png`.

### 11.9 구역 씬 (맵 재조립)
- 구역 = 라이트맵 굽기 단위. 정의는 `scripts/game/world/zones/zone_<구역>.gd`(ZoneBuilder로 부품·맞춤 지오메트리·바닥·빛 배치), 목록은 `ZoneCatalog`.
- `godot --headless --path . --script tools/build_zones.gd` -> `scenes/raid/zones/<구역>.tscn` + `<구역>/cell_x_z.res`.

- `IndustrialMap.add_zone()`이 구역 씬이 있으면 붙이고 충돌을 내비메시 기준에 넣는다. 게임플레이(루팅·엄폐·순찰·탈출)는 맵 코드 그대로.
- 진행: 공장 홀(`factory_hall`) 시범 완료. 나머지 구역은 옛 코드 지오메트리.
- 태블릿 굽기: `res://scenes/raid/zones/<구역>.tscn`을 열고 LightmapGI 선택 -> 굽기 (프로브 끔·품질 Low·바운스 2가 미리 설정됨) -> `<구역>.lmbake`로 저장 -> 씬 저장.
