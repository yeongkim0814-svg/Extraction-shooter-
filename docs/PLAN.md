## 확정된 결정

| 항목 | 결정 |
|---|---|
| 장르 | Extraction shooter, 테트리스형(그리드) 인벤토리·스태시 |
| 엔진 | Unity 6 LTS, URP |
| 시점 | FPS |
| 플랫폼 | 모바일(폰·태블릿) + 웹. 우선순위 Android → 데스크톱 웹 → 모바일 웹. iOS는 Mac/Xcode 필요 |
| 그래픽 | 세미리얼 PBR. M10에서 스타일라이즈드 전환 여부 재결정 → 전환 가능한 구조로 설계 |
| 첫 맵 | 버려진 산업단지 |
| 적 | 인간형 무장 AI (Scav 계열) |
| 모드 | PvE 먼저, 멀티플레이는 이후 (서버 권한 구조로 대비) |
| 아이템 형태 | 직사각형 전용 |
| 콘텐츠 | 아이템·탄약·무기·부착물·약품·장비 지속 확장 → 데이터 주도 설계 |
| 수색 | 컨테이너 수색 단계 MVP 포함 |
| 총기 모딩 | 부품 트리 구조는 MVP부터, 콘텐츠·전용 화면은 MVP 이후 |
| 거래소 | 멀티플레이 단계에서 추가 (PvE는 NPC 상인) |

## 개발 환경 제약

| 항목 | 상태 | 영향 |
|---|---|---|
| Unity 에디터 | 클라우드 개발 컨테이너에서 사용 불가 (다운로드 차단, 라이선스·GPU·디스플레이 없음) | Unity 빌드·씬 편집은 로컬에서 |
| .NET SDK | 설치 가능 | 순수 C# 코어는 컨테이너에서 빌드·테스트 |

→ 게임 규칙은 Unity 비의존 순수 C# 코어에 두고 TDD로 검증한다. Unity 레이어(UI·씬·프리팹)는 얇게 유지하고 로컬에서 검증한다.

## 검증 방식

- M0~M3: 컨테이너에서 `dotnet test`, PR마다 GitHub Actions CI
- M4 이후: 마일스톤별 수동 확인 체크리스트 + 실기기(Android)·브라우저(Chrome/Safari) 테스트, Unity Profiler로 예산 확인

## 위험

1. **세미리얼 + FPS + AI + 모바일 웹**은 성능 부담이 큼 → 플랫폼 우선순위 고정, 모바일 웹은 최저 티어
2. Unity 레이어는 컨테이너에서 컴파일 불가 → 로직은 Core로, Unity 코드는 얇게, 에러 로그 공유로 반복
3. 모델링 작업량이 최대 병목 → 플레이스홀더로 게임플레이 먼저 완성, 아트는 M10에 집중
4. `ProjectSettings`는 에디터가 생성 → M4는 로컬에서 빈 URP 프로젝트 생성 후 푸시
