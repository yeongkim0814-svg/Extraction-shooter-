## 확정된 결정

| 항목 | 결정 |
|---|---|
| 장르 | Extraction shooter, 테트리스형(그리드) 인벤토리·스태시 |
| 엔진 | **Godot 4.7.x**, GDScript(정적 타입) |
| 렌더러 | Android = Mobile, 웹 = Compatibility |
| 시점 | FPS |
| 플랫폼 | 모바일(폰·태블릿) + 웹. 우선순위 Android → 데스크톱 웹 → 모바일 웹 |
| 그래픽 | 세미리얼 PBR. M10에서 스타일라이즈드 전환 여부 재결정 → 전환 가능한 구조로 설계 |
| 첫 맵 | 버려진 산업단지 |
| 적 | 인간형 무장 AI (Scav 계열) |
| 모드 | PvE 먼저, 멀티플레이는 이후 (서버 권한 구조로 대비) |
| 아이템 형태 | 직사각형 전용 |
| 콘텐츠 | 아이템·탄약·무기·부착물·약품·장비 지속 확장 → 데이터 주도 설계 |
| 수색 | 컨테이너 수색 단계 MVP 포함 |
| 총기 모딩 | 부품 트리 구조는 MVP부터, 콘텐츠·전용 화면은 MVP 이후 |
| 거래소 | 멀티플레이 단계에서 추가 (PvE는 NPC 상인) |
| 모델링 | Nomad Sculpt(탭) 주력, Blender는 PC 세션에서 보조 |

## 개발 환경

| 누가 | 기기 | 도구 | 역할 |
|---|---|---|---|
| 사용자 | 갤럭시 탭 | Godot 안드로이드 에디터, Nomad Sculpt, Git | 씬 배치·그레이박스·모델링·플레이 테스트 |
| 사용자 | PC (가끔) | Blender, 라이트맵 베이크(필요 시) | 몰아서 하는 작업 |
| Claude | 클라우드 컨테이너 | 헤드리스 Godot, GUT, Chromium | 코드·데이터·테스트·웹 빌드 검증·스크린샷 |

확인된 것: 컨테이너에서 Godot 릴리스·npm 접근 가능, Chromium 설치됨. Unity를 쓰지 않는 이유는 에디터가 데스크톱 전용이라 탭에서 작업할 수 없기 때문.

## 검증 방식

- 컨테이너: 헤드리스 GUT 테스트, 웹 빌드를 Chromium으로 실행해 콘솔 에러·스크린샷 확인, PR마다 CI
- 탭: 마일스톤별 체크리스트(터치 조작감·프레임·발열)로 플레이 테스트

## 위험

1. **웹 그래픽 상한:** Compatibility 렌더러라 세미리얼 표현이 제한됨 → 텍스처·베이크 위주로 설계, M10 스타일 체크포인트에서 재판단
2. **탭 에디터 한계:** 작은 화면·터치 조작 → 키보드·마우스 연결 권장, 정밀 작업은 컨테이너(코드)로 넘김
3. **라이트맵 베이크:** 탭에서 불가하면 PC 세션 필요 (M4에서 확인)
4. **동시 편집 충돌:** 같은 `.tscn`을 양쪽에서 편집하지 않도록 씬 단위로 분담
5. **모델링 병목:** Nomad Sculpt는 정밀 하드서피스에 약함 → 부품 분할 + 텍스처 디테일, 부족분만 Blender. 그 전까지 플레이스홀더로 게임플레이 먼저 완성
6. **세미리얼 + FPS + AI + 모바일 웹** 성능 부담 → 플랫폼 우선순위 고정, 모바일 웹은 최저 티어
